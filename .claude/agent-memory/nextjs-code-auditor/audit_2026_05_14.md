Audit date: 2026-05-14

## Critical (1)
- All Prisma queries in src/lib/db/ have NO userId filter. When auth is added, every user will see every other user's data unless filters are added at that time.

## High (2)
- getDashboardCollections: No `take` limit — loads ALL collections with full nested items+itemType for each. Will degrade badly at scale.
- getSidebarData: Same pattern — loads ALL collections with full item+itemType joins for dominant-color computation. Should be capped or computed differently.

## Medium (4)
- Missing loading.tsx for /dashboard route — no loading state during server-side data fetching
- Root page.tsx has no redirect to /dashboard
- Sidebar user section is hardcoded (name, email, avatar initial) — not a data bug yet but will need replacing when auth lands
- App metadata in layout.tsx is still the Create Next App default boilerplate

## Low (3)
- getDashboardCollections and getSidebarData duplicate the dominant-color computation logic — candidate for shared util
- TopBar search input is non-functional (no onChange/state) — placeholder UI only
- TopBar "New Collection" and "New Item" buttons have no onClick handlers

## Already Correct
- Promise.all parallelization in dashboard/page.tsx
- Prisma singleton pattern in src/lib/prisma.ts
- itemSelect const + mapItem function pattern in items.ts (efficient select)
- Tailwind v4 CSS @theme config (correct, no tailwind.config.ts)
- No `any` types found anywhere
- No hardcoded secrets in source files
- .env is gitignored
